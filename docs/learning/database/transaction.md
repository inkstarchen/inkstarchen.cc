- 原子性要求
	- 系统必须确保部分执行的事务不能反映在数据库中
- 持续性要求
	- 一旦事务被提交，即使出现系统错误，更新也应该被保持、
- 一致性要求
	- 在执行事务前数据库必须保持在一致性状态下
- 隔离性要求
	- 事务之间应当相隔离，不应存在中间结果被获取的情况
	  
并行执行的优点：增加处理器和磁盘利用率、减少平均响应时间

并行的一些异常情况
- 修改丢失，同时执行的两个事务都在原数据上修改，便会丢失其中一个修改。
- 读脏数据：一个事务被撤销，而事务二读到修改后的数据
- 不可重复读，在修改前后读取
- 幻读：在插入前后获取数据

并行事务需要调度机制以确保事务的正确执行

假如调度$S$能够通过交换一系列不冲突的指令得到$S'$我们就说这两个调度是**冲突等价(conflict equivalent)**

如果一个调度与一个串行调度冲突等价，则称其为**冲突可串行化(conflict serializable)**

### 视图可串行化

两个调度视图等价假如：
- $S$中事务$T_1$ 读了对象$A$的初始值，则$S'$中$T_1$ 也读了$A$的初始值
- $S$中事务$T_1$读了事务$T_2$修改过的$A$值，$S'$中$T_1$也读了$T_2$修改过的$A$值
- $S$ 中事务$T_1$写了$A$的最终值，$S'$中$T_1$也写了$A$的最终值

一个调度是视图可串行化的假如它与串行调度是视图等价的

一个调度是冲突可串行化的的当且仅当他的前驱图是无环的

### 可恢复调度
事务一读事务二写的数据，那么事务二的提交要在事务一前面，才是可恢复调度
